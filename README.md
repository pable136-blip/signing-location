# 행사 근무자 QR 출석

행사장 부스에 두던 **종이 근무자 서명부를 QR 출석으로** 바꾼다.
부스 태블릿이 QR 을 띄우고, 근무자는 휴대폰 기본 카메라로 찍어 출근·퇴근을 누른다.
기록은 구글 시트에 쌓인다(별도 서버·비용 없음).

## 「QR 사진으로 다른 곳에서 출석」 차단

| 수법 | 막는 장치 | 판정 위치 |
|---|---|---|
| QR 을 사진·캡처해 단톡방에 공유 | QR 이 **30초마다 바뀌고 약 1~1.5분 뒤 만료**. 토큰은 부스키로 만든 HMAC 이라 위조 불가 | 서버 |
| 스캔한 링크(주소)를 복사해 전달 | 링크에 같은 토큰이 들어 있어 똑같이 만료. 출석 화면은 열리자마자 주소창에서 토큰을 지움 | 서버 |
| 1분 안에 사진을 받아 멀리서 즉시 찍기 | 출석 순간 휴대폰 **GPS 가 행사장 반경 밖이면 거부**, GPS 오차 100m 초과·2분 넘은 위치값도 거부 | 서버 |
| 현장 동료가 내 이름으로 대신 찍기 | **근무자 1명 = 휴대폰 1대 고정**. 한 폰으로 두 사람 출석 불가, 처음 쓴 폰이 아니면 거부 | 서버 |
| 행사 전날·끝난 뒤 출석 | 행사 시작~종료 일시 밖이면 거부 | 서버 |
| 명단에 없는 사람 | (선택) 「사전명단만허용 = Y」 로 바꾸면 명단의 이름+연락처 뒤 4자리만 허용. 기본은 N — 명단 없이 첫 출석 때 자동 등록 | 서버 |

거부된 시도는 모두 **「거부기록」 시트**에 사유·행사장까지 거리·기기와 함께 남으므로,
반복해서 원거리 시도를 한 사람을 사후에 확인할 수 있다.

> 한계: 안드로이드 「가짜 GPS」 앱으로 위치를 조작하는 것은 웹 브라우저에서 완전히 감지할 수 없다.
> 다만 그 경우에도 **1분 안에 새 QR 사진을 받아야** 하므로 공모자가 현장에 있어야 하고,
> 기기 고정 때문에 그 공모자 폰으로 대신 찍을 수도 없다. 더 강하게 하려면 운영 시
> 부스 담당자가 「출석기록」 시트를 띄워 두고 출석자 얼굴과 대조하면 된다.

## 개인정보·보안 (외부 유출 방지)

실명 등 개인정보는 **본인 구글 계정의 스프레드시트 한 곳에만** 저장된다.

| 항목 | 처리 |
|---|---|
| GitHub 저장소·웹 화면 | 코드뿐, 개인정보 없음. 저장소가 공개여도 명단·기록은 보이지 않는다. 외부 CDN·분석 스크립트 없음(폰트·QR 라이브러리 자체 포함) |
| 웹 API(Apps Script) | 명단·기록을 **돌려주는 기능 자체가 없다**. 응답은 본인 출석 결과뿐. 행사명도 유효한 QR 토큰이 있어야 응답 |
| 다른 사람 이름 | 대리출석 거부 메시지에도 **누구의 폰인지 이름을 표시하지 않음** |
| 위치 | 휴대폰 위도·경도는 거리 계산에만 쓰고 **저장하지 않음**. 「행사장까지 거리(m)」만 남김 |
| 연락처 | 뒤 4자리만. 브라우저 정보 수집 안 함. 부서명 칸 없음 |
| 기기ID | 브라우저가 만든 무작위 값(휴대폰 고유번호 아님) |
| 보존기간 | 메뉴 **출석관리 → 보존기간 지난 기록 삭제** (기본 365일, `RETENTION_DAYS`) |
| 장난 요청 | 없는 행사ID 로 들어온 요청은 시트에 기록조차 하지 않음 |

**담당자가 지킬 것**
- 스프레드시트 **공유 설정은 「제한됨」 유지** — 「링크가 있는 모든 사용자」 로 바꾸지 말 것. 꼭 필요한 담당자만 이메일로 공유.
- 시트를 엑셀·CSV 로 내려받았다면 이 저장소에 올리지 말 것(`.gitignore` 로 막아 둠).
- 부스키는 근무자·단톡방에 공유하지 말 것.
- Apps Script 배포의 「액세스: 모든 사용자」 는 *웹 주소로 출석을 보낼 수 있다* 는 뜻일 뿐, 시트를 열람할 수 있다는 뜻이 아니다.
- **기관 정보보안 지침 확인 권장**: 공공기관은 직원 개인정보를 외부 클라우드(구글)에 두는 것을 제한하는 경우가 있다.
  우려되면 「이름」 칸에 실명 대신 **근무자 번호(예: A017)** 를 쓰게 하고, 번호↔실명 대응표는 내부망에만 보관하면
  구글 시트에는 실명이 전혀 남지 않는다.

## 부서 배포 — 담당자가 각자 사용

부서에는 **`https://pable136-blip.github.io/signing-location/`** 주소 하나만 공유하면 된다.
첫 화면(`index.html`)에 설치·운영 방법이 모두 있고, 담당자는 코드를 고칠 필요가 없다.

- 담당자마다 **본인 구글 시트**로 운영 → 팀끼리 근무자 명단·기록이 섞이거나 보이지 않는다.
- 설치: 새 시트 → Apps Script 에 「서버 코드 복사」 버튼으로 붙여넣기 → 웹 앱 배포(실행: 나, 액세스: 모든 사용자).
- 행사: 시트 메뉴 **출석관리 → 새 행사 만들기**(행사명·날짜) → 부스 화면에 서버 주소·행사ID·부스키 입력
  → 부스 자리에서 **이 자리를 행사장 위치로 등록** → **QR 띄우기**.
- QR 에는 서버 주소 대신 짧은 배포 ID 만 들어가며, 출석 화면은 그 ID 로 `script.google.com` 에만 연결한다
  (다른 서버로 개인정보를 보내도록 QR 을 조작할 수 없음).
- 부서가 시트 하나를 같이 쓰고 싶다면 `config.js` 의 `API_URL` 에 그 웹 앱 주소를 넣는다. 그러면 부스 화면에서 서버 주소 칸이 사라진다.

## 구성

```
index.html          부서 안내 첫 화면 — 설치·운영 방법, 서버 코드 복사 버튼
booth.html          부스 태블릿용 — 서버 주소·행사ID·부스키 입력, 행사장 위치 등록, 30초마다 바뀌는 QR
checkin.html        근무자 휴대폰용 — QR 스캔 시 열림, 이름·연락처 뒤 4자리 + GPS 로 출근/퇴근
api.js              웹 앱 주소 ↔ 배포 ID 변환(script.google.com 만 허용)
config.js           (선택) 부서 공용 서버 주소
apps-script/Code.gs 서버(구글 시트에 붙이는 Apps Script) — 메뉴: 새 행사 만들기·기기 초기화·보존기간 삭제
vendor/qrcode.js    QR 생성 라이브러리(MIT, kazuhikoarase/qrcode-generator 1.4.4)
```

## 시트 메뉴 「출석관리」

| 메뉴 | 하는 일 |
|---|---|
| 새 행사 만들기 | 행사명·날짜를 묻고 행사ID·부스키를 만들어 보여 줌 |
| 선택한 근무자 기기 초기화 | 「근무자」 탭에서 선택한 사람의 휴대폰 고정을 풂(폰 교체 시) |
| 시트 초기 설정 | 탭·머리글 생성(처음 시트를 열면 자동 실행) |
| 빈 행사ID·부스키 채우기 | 「행사」 탭에 직접 적은 행의 빈 ID·키 생성, 부스키 재발급 |
| 보존기간 지난 기록 삭제 | 출석·거부 기록 중 365일 지난 것 삭제 |

## 설정값 (Code.gs 맨 위 `CONFIG`)

| 항목 | 기본 | 뜻 |
|---|---|---|
| `SLOT_SECONDS` | 30 | QR 교체 주기(초) — 부스 화면이 서버에서 받아 씀 |
| `SLOTS_PAST` | 2 | 지난 QR 몇 개까지 인정할지(스캔 지연 허용) |
| `MAX_ACCURACY_M` | 100 | GPS 오차 허용 한도(m) |
| `DEFAULT_RADIUS_M` | 200 | 행사 시트에 반경이 비었을 때 |
